## Ce que tu dois faire, dans l'ordre
1. **Versions** : vérifie *au moment du build*, dans le registre officiel (index.crates.io, NuGet, Maven Central/Google Maven, pub.dev/storage.googleapis.com, download.qt.io, tags git), la **dernière version stable** de chaque outil et dépendance utilisés, et mets tout à jour (pas de bêta ni de RC sauf s'il n'existe pas de stable ; dans ce cas dis-le). Note chaque version exacte, sa source et la date vérifiée dans `STACK-NOTES.md`, et écris-les dans le champ `"version"` du JSON.
2. **Revue de code contre la documentation officielle** de la version utilisée (pages web officielles, docs.rs, guides, API) : relis TOUT le code de ton app, compare chaque usage d'API à la doc (signatures, sémantique, recommandations de performance officielles, API dépréciées, idiomes recommandés pour listes virtualisées, canvas, threads, timers, texte, images). Liste chaque écart ou bug trouvé et sa correction, avec l'URL de la doc qui le justifie, dans une section « Revue » de `STACK-NOTES.md`. Relis aussi la conformité stricte à la spec (contenu, tailles, scripts déterministes, PRNG, flux, file bornée, scénarios).
3. **Spec v2** : marqueurs `BENCH:measure_start` / `BENCH:measure_end` sur stdout (flush), nouveau scénario `input` (carré 200×200 en (100,100) noir/blanc à chaque Espace, pendant que la liste défile), `ops.gc` pour les runtimes managés, `ops.not_rendered`, `unsupported`, `version`. Définition de frame uniforme (fin de présentation ; pas de contournement de plafond par API **privée** : si un plafond 60 Hz n'est pas désactivable publiquement, garde-le et documente). Chemins : aucun chemin absolu codé en dur (`BENCH_ROOT`, `--assets`, `BENCHCORE_LIB`).
4. **Correction et build** release ; garde les erreurs exactes dans `stacks/<stack>/logs/`.
5. **Vérification** : pour chaque scénario, lance `python3 -I harness/verify_gui.py <stack> "<cmd>" <scenario> [args]` et **regarde la capture PNG produite** (outil Read sur l'image) : le rendu doit correspondre à la spec (lignes, pastilles, prix, dégradés, ombres, clip arrondi, graphe, texte CJK/emoji/RTL, vignettes, carré du scénario input). Ce qui n'est pas rendu → `ops.not_rendered`, documenté. Puis une fumée courte par scénario avec le harnais : `python3 -I harness/run_bench.py --stack <stack> --cmd "<cmd>" --scenario <s> --duration 8 --runs 1 --outdir /tmp/<stack>-smoke` (vérifie `markers: True`, `sum_heights`, `input_latency` cohérente). **Pas de mesures officielles** (≤15 s par scénario) ; ne lance jamais `pkill Xvfb` (tes Xvfb à toi, displays :200–:699 ; le harnais utilise :90–:98, verify_gui :390).
6. **Livrables** : code à jour, `build.sh` (reproductible, versions épinglées), `run.sh` ou commande exacte pour `harness/stacks.tsv` (avec `${ROOT}`), `STACK-NOTES.md` réécrit (versions, revue, écarts, limites, tailles disque du déploiement et `ldd`, lignes de code, temps de build), logs.
