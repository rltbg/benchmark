## 1. Architecture de rendu

### 1.1 Modèle général : arbre d'items retenu + rendu « partiel » par rectangles
- **Scène retenue** (arbre d'`Item` instanciés, propriétés réactives), pas de mode immédiat. Il n'y a **pas d'API canvas/immediate-mode** pour le renderer logiciel : le seul crochet de dessin custom est `set_rendering_notifier` (contextes GL/wgpu/Vulkan uniquement) ; le dessin « libre » CPU passe par `Image` construite depuis un `SharedPixelBuffer` ou par des `Path`/`Rectangle`. [LU `sw/lib.rs:3059-3066` (box shadow = `// TODO`), `core/graphics/image.rs:791-806` (doc `Image`/`SharedPixelBuffer`)]. Conséquence pour G1-G5 : « un item par forme » est la seule voie native pour le logiciel (à documenter dans NOTES).
- De « une propriété change » à « un pixel écrit » (X11 + softbuffer, chemin logiciel) :
  1. `Property::set` compare (`PartialEq`) puis `mark_dirty` → parcours récursif de la liste intrusive des dépendants (§3) [LU `core/properties.rs:1029-1060`, `851-870`].
  2. Un `PropertyTracker` de la fenêtre (`redraw_tracker`, `PropertyTracker<false, WindowRedrawTracker>`) dépend de tout ce que le rendu a lu ; son `notify()` appelle `WindowAdapter::request_redraw()` [LU `core/window.rs:498-508`, `562`, `700-704`, `1855`].
  3. `WinitWindowAdapter::request_redraw` : `pending_redraw.replace(true)` puis `frame_throttle.request_throttled_redraw` [LU `winit/winitwindowadapter.rs:1849-1856`]. Sous X11 (≠ Wayland) c'est un **Timer Slint de 16 ms** (§2).
  4. Le tick du timer appelle `winit_window.request_redraw()` ; winit livre `RedrawRequested` dans la même itération de boucle, après les événements utilisateur [LU `winit/frame_throttle.rs:46-71,86-92` ; `[winit-0.30.13] platform_impl/linux/x11/mod.rs:549-570`] → `WinitWindowAdapter::draw()` (`pending_redraw=false`, `renderer.render`) [LU `winit/winitwindowadapter.rs:841-879,1290`].
  5. `WinitSoftwareRenderer::render` : `softbuffer::Surface::resize`, `buffer_mut()`, détermine l'`age` du tampon → `RepaintBufferType` {1→ReusedBuffer, 2→SwappedBuffers, sinon NewBuffer}, appelle `SoftwareRenderer::render`, puis `present_with_damage(rectangles)` seulement si la région est non vide [LU `winit/renderer/sw.rs:86-160`, `118` (lit `SLINT_LINE_BY_LINE` **à chaque frame**), `135-150`].
  6. softbuffer X11 : `age()` renvoie **1 dès qu'un tampon a été présenté**, 0 sinon ; `resize` (taille changée) remet `buffer_presented=false` ⇒ frame pleine après chaque redimensionnement ; présentation par **MIT-SHM `shm_put_image` par rectangle de dommage**, sinon repli `put_image` du **tampon entier** (dommage ignoré) ; `buffer_mut()` bloque (`finish_wait`, aller-retour X) tant que le `put_image` précédent n'est pas terminé [LU `[softbuffer-0.4.8] src/backends/x11.rs:313-338,343-351,416-422,425-512`]. Sous Xvfb le SHM est normalement disponible [HYP].
- **Suivi des zones sales (damage)** : `PartialRenderingState::apply_dirty_region` → `PartialRenderer::compute_dirty_regions` parcourt **tout l'arbre d'items à chaque frame** (`visit_items`, ordre arrière→avant), recalcule la géométrie/boîte englobante/transformation de chaque item et la compare à un cache (slab indexé par `CachedRenderingData`) ; l'item est « dirty » si sa géométrie a changé, si son rang parmi ses frères a changé, ou si son `PropertyTracker` de rendu est sale [LU `core/partial_renderer.rs:449-710`, `918-957`]. Les Clip/Opacity propagent `must_refresh_children` [LU `:572-590`].
  - **La région sale est limitée à 3 rectangles** (`DirtyRegion::MAX_COUNT = 3`) ; au-delà on fusionne avec le rectangle dont l'union agrandit le moins l'aire [LU `core/partial_renderer.rs:271,297-330`]. Dès que plus de 3 zones disjointes bougent (nuage de formes animées), la région tend vers la **boîte englobante de tout** ⇒ repeinture quasi plein cadre.
  - Le coût du parcours est **O(items de l'arbre)** même si un seul pixel change (§1.4, §3).
  - En mode `NewBuffer` (1ʳᵉ frame, après redimensionnement) le cache est vidé et tout est dessiné sans `PartialRenderer` ; la frame suivante (age=1) reconstruit le cache : **deux frames pleines** consécutives [LU `sw/lib.rs:628-631,687-697`].
- **Passes** : (a) instanciation des répéteurs (`ensure_tree_instantiated`, appelé au début de **chaque** `draw_contents`) [LU `core/window.rs:794-815,1839-1842`] ; (b) compute_dirty_regions ; (c) remplissage du fond sur la région sale ; (d) rendu des items par `render_component_items` → `render_item_children` (récursion avec `save_state/restore_state`, `filter_item` pour l'élagage) [LU `core/item_rendering.rs:202-252`, `sw/lib.rs:661-700`].
- **Threads** : tout (propriétés, layout, rendu, X11) tourne sur **le thread UI unique** ; Slint n'a pas de thread de rendu ni de rastérisation parallèle côté logiciel [LU : `Rc`/`RefCell`/`Cell` partout, `Property` non `Send`, `core/graphics/image.rs:791-795` « Image is not Send »]. Les autres threads n'interagissent que via `invoke_from_event_loop` (§9).

### 1.2 Moteur de rastérisation logicielle maison (`internal-renderers-software`)
Pas Skia/tiny-skia : un rasteriseur ligne-par-ligne en entiers/virgule fixe [LU `sw/draw_functions.rs`, `sw/fixed.rs`], `zeno` pour les chemins [LU `sw/path.rs:1-8`], `swash` pour les glyphes [LU `sw/fonts/vectorfont.rs:207-210`], `parley`/`harfrust` pour la mise en forme (§5).
- `RenderToBuffer` dessine **immédiatement, dans l'ordre du peintre**, chaque primitive dans le tampon (`foreach_ranges` : pour chaque bande de lignes de la région sale et chaque plage, appelle un closure par ligne) [LU `sw/lib.rs:1839-1890,1905-2030`]. Pas de tri/culling d'occlusion ⇒ **surdessin intégral** (coût ∝ somme des aires empilées).
- **Chemins rapides** : rectangle uni opaque → `blend_slice` = `slice.fill` (quasi memset) ; translucide → `blend` scalaire par pixel [LU `sw/lib.rs:1952-1956`, `sw/draw_functions.rs:843-851`] ; texture RGBA prémultipliée, échantillonnage au **plus proche voisin** en virgule fixe 8 bits avec boucle de tuilage [LU `sw/draw_functions.rs:20-183`, `185-260`] ; glyphes = textures alpha pré-rastérisées blittées avec cache (4 sous-positions horizontales) [LU `sw/fonts/vectorfont.rs:29-70,175-230`, `sw/lib.rs:3300-3420`].
- **Chemins lents** : 
  - texture RGBA **non prémultipliée** : `PremultipliedRgbaColor::premultiply` **par pixel** [LU `sw/draw_functions.rs:208-221`] ; code scalaire (pas de SIMD explicite) [LU, lecture des boucles].
  - rectangle arrondi/bordure : calcul par ligne avec `isqrt` en virgule fixe, anti-aliasing par pixel de bord [LU `sw/draw_functions.rs:316-420`].
  - dégradé linéaire/radial/conique : calcul par pixel [LU `sw/draw_functions.rs:551-700`]. Fond de fenêtre en dégradé : non géré (`// TODO: gradient background`) [LU `sw/lib.rs:677`].
  - **Chemins vectoriels** : pour *chaque* `Path` et *chaque* frame, alloue un `vec![0u8; w*h]` (boîte du chemin), rastérise tout le masque `zeno`, puis parcourt **tous** les pixels de la boîte ∩ clip avec fusion par pixel ; le remplissage est figé en `Fill::NonZero` ; `zeno_commands.clone()` pour le remplissage ; **pas de pointillés** (aucune propriété `dash` dans `Path`) [LU `sw/path.rs:61-124`, `sw/lib.rs:2977-3057`, `comp/builtin_elements.rs:3044-3057`].
  - **Opacité = multiplication d'alpha par item** (`apply_opacity` multiplie `alpha` de l'état), pas de composition de groupe hors-écran : un groupe semi-transparent dont les enfants se chevauchent est rendu différemment (fuite des enfants) et `Layer`/`cache-rendering-hint` n'est pas supporté (`visit_layer` « Not supported ») [LU `sw/lib.rs:3104-3106`, `core/item_rendering.rs:614-634`, `docs/.../reference/common.mdx:263-271` « Not all rendering backends support this »].
  - **Non rendus** : `BoxShadow` (drop/inner shadow) = no-op ; **rayon du `Clip`** ignoré (clip rectangulaire, `// TODO: handle radius`) ; `rotate`/`scale` = `// TODO (#6068)` et `supports_transformations() == false` ; pas de flou de groupe dans le langage (seul `drop-shadow-blur` existe) [LU `sw/lib.rs:1266-1268,3059-3102`, `comp/builtin_elements.rs:644-681`]. ⇒ G1 `shadow`, G1 `clip` (arrondi), G4 rotation, G5 `blur` : `unsupported`/`not_rendered` à consigner, ne pas émuler avec des images pré-rendues.
- Texte : voir §5. Images : voir §7.

### 1.3 Autres renderers (pour la revue d'équité ; hors configuration cible)
- **Défaut du crate `slint`** : features `renderer-femtovg` + `renderer-software` ; `default_renderer_factory` choisit **FemtoVG (OpenGL)** si `supports_opengl`, sinon logiciel [LU `api/rs/slint/Cargo.toml:23-31`, `winit/lib.rs:139-157`]. Sans `SLINT_BACKEND`, un banc « logiciel » peut donc **tourner sur llvmpipe/OpenGL** sans que personne s'en aperçoive. Sélection : `SLINT_BACKEND=winit-software` (ou `sw`/`software`) [LU `internal/backends/selector/lib.rs:109-146,155-166`] ou `BackendSelector::renderer_name("software")`.
- **FemtoVG** : redessine toute la scène à chaque frame (aucun `PartialRenderingState` dans `femtovg/lib.rs`), clip par `scissor` rectangulaire, transformations supportées via la pile de matrices de femtovg [LU `femtovg/lib.rs:157-330`, `femtovg/itemrenderer.rs:617-640,784-816`].
- **Skia** : le chemin « software » de Skia (`SoftwareSurface` via softbuffer) active le rendu partiel (`use_partial_rendering() = true`), `clip_rrect` rond avec anti-alias, `save_layer_alpha` pour les groupes d'opacité, caches `image_cache`/`layer_cache`/`path_cache`/`box_shadow_cache` (ombre floue en `MaskFilter::blur`) [LU `skia/software_surface.rs:229-231`, `skia/itemrenderer.rs:759-822,936-1000`, `skia/lib.rs:343,396-415`]. Ordre des surfaces candidates : wgpu(vulkan), OpenGL, wgpu, **software** [LU `skia/lib.rs:274-290`]. La compilation de `skia-safe` est lourde ; hors périmètre mesuré ici.

### 1.4 Coût fixe par frame du renderer logiciel [LU + HYP]
À chaque frame effectivement dessinée, même si un seul item change :
1. `ensure_tree_instantiated` : descend récursivement dans **tous** les répéteurs (`ensure_children_instantiated` clone un `Vec` de tous les `Rc` d'instances à chaque appel) [LU `core/model/repeater.rs:702-712,883-885`, `core/window.rs:794-815`] ⇒ O(instances de répéteur).
2. `compute_dirty_regions` : par item : `ItemRc::new` (clone de Rc), lecture de la géométrie (4 `Property` suivies si non constantes), `bounding_rect`, `clipped_screen_rect`, lookup slab, comparaisons, enregistrement du tracker de l'item comme dépendance de `redraw_tracker` [LU `core/partial_renderer.rs:449-640`].
3. `redraw_tracker.evaluate_as_dependency_root` **vide la liste de dépendances (une libération par nœud) puis la reconstruit (une allocation par dépendance relue)** [LU `core/properties.rs:1359-1366`, `core/window.rs:1855`].
⇒ **coût ≈ O(N_items) allocations/libérations par frame** ; ordre de grandeur [HYP] 0,2–0,6 µs/item.
- Une frame « idle » supplémentaire suit chaque rafale (voir §2) : elle refait 1-3 sans pixel.

## 2. Boucle d'événements et cadence

- Backend : `winit 0.30.13` + `softbuffer`. Boucle `ApplicationHandler` : `new_events` → `ControlFlow::Wait` puis `update_timers_and_animations()` ; `about_to_wait` → `request_redraw()` pour toute fenêtre ayant `has_active_animations()` ; puis, si `Wait`, `ControlFlow::wait_duration(prochain timer)` [LU `winit/event_loop.rs:213-270`, `core/context.rs:217-233`].
- `update_timers_and_animations` : `update_animations(now)` (met à jour `global_instant`), `activate_expired` des timers, puis `ChangeTracker::run_change_handlers()` [LU `core/context.rs:217-222`].
- **Horloge : millisecondes entières** (`Instant(u64)` en ms ; `now()` = `duration_since_start().as_millis()`) [LU `core/animations.rs:176-179,213-216`]. L'échéance d'un timer répété est `now_ms + interval` calculée **au début de l'activation** (avant le callback), donc la période n'inclut pas le temps de dessin tant qu'il est < intervalle ; si le dessin dépasse l'intervalle, le timer est échu immédiatement à l'itération suivante, **sans rattrapage de frames** [LU `core/timers.rs:344-385,476-481`].
- **Origine du 16 ms / 62,5 Hz** [LU] : sous X11 `create_frame_throttle` renvoie `TimerBasedFrameThrottle` ; l'intervalle est `(1000*1000)/refresh_rate_millihertz` en **division entière** avec défaut 60000 mHz quand le moniteur ne rapporte rien ⇒ `1_000_000/60_000 = 16` ms (au lieu de 16,67) ⇒ **62,5 Hz** [`winit/frame_throttle.rs:13-34,46-71`]. Sous Wayland le throttle est celui de winit (`request_redraw` direct, frame callback compositeur) [`:86-98`]. Pas de vsync sous Xvfb.
- **Coalescence** : `request_redraw` est idempotent tant que `pending_redraw` est vrai [LU `winit/winitwindowadapter.rs:1849-1856`] ; le timer ne démarre que s'il ne tourne pas [`frame_throttle.rs:47-49`].
- **Séquence réelle d'une rafale** [LU, `frame_throttle.rs:46-71` + `winitwindowadapter.rs:841-846`] :
  - changement à t₀ (timer arrêté) → timer démarré, **premier tick à t₀+16 ms** (jamais immédiat) ⇒ **latence minimale touche→pixel ≥ 16 ms** [HYP : +travail de rendu + SHM + X].
  - à chaque tick : `redraw_now` (inconditionnel) puis `keep_running = pending_redraw()` — évalué **avant** que la frame n'ait tourné, donc vrai ⇒ le timer reste actif ; au tick suivant `redraw_now` redessine une frame **potentiellement vide** (dommage vide ⇒ aucun `present`, mais tout le coût §1.4 est payé) puis s'arrête si plus rien n'est en attente. Donc *une frame idle de coût O(N_items) suit chaque rafale*.
  - les animations (`animation_tick` → `set_has_active_animations`) ré-arment `request_redraw` depuis `about_to_wait` à chaque itération [LU `core/animations.rs:298-304`, `winit/event_loop.rs:250-258`].
- **Événements utilisateur** (`invoke_from_event_loop`) : voir §9 ; **toute la file est vidée dans une itération** avant les redraws (`while let Ok(event) = user_receiver.try_recv()`) ⇒ un flot soutenu empêche l'itération de se terminer (gel potentiel) [LU `[winit-0.30.13] x11/mod.rs:549-552`].
- **Frame « tient 60 Hz »** : dès que le dessin < 16 ms, la cadence est 62,5 Hz fixe, indépendante du coût ; dès qu'il dépasse, la cadence = 1000/(coût+surcoût d'itération) avec **dégradation douce** (pas d'effondrement par file) [HYP issu du LU ci-dessus].
- `refresh_rate_millihertz` : si XRandR de Xvfb renvoie un taux non nul (p. ex. 75 Hz) l'intervalle change (13 ms) ; la mesure « 62,5 Hz » du brief est cohérente avec `None`→60000 ou 60 Hz [HYP].

## 3. Moteur de propriétés / liaisons / réactivité

- `Property<T>` = `PropertyHandle` (un pointeur 8 o, bits de poids faible = {lock, pointe-vers-binding}) + `UnsafeCell<T>` ; la liste des dépendants est **intrusive doublement chaînée** dont la tête est stockée dans le handle lui-même quand il n'y a pas de binding [LU `core/properties.rs:119-300,564-640,892-905`].
- Un `BindingHolder` (`Box` alloué par binding) porte : tête des dépendants, **liste simplement chaînée de `DependencyNode` (un `alloc` par dépendance enregistrée)**, vtable (evaluate/mark_dirty/intercept_set…), bit `dirty` [LU `core/properties.rs:447-480,483-560`, `single_linked_list_pin::push_front` `:57-70`].
- **Évaluation paresseuse** : `get()` → `update()` : si le binding est `dirty`, **efface tous ses nœuds de dépendance (free de chacun)**, positionne `CURRENT_BINDING` (thread-local), évalue, relit/re-enregistre les dépendances (**malloc par propriété lue**) [LU `core/properties.rs:758-785`, `788-806`, `962-1000`].
- **Propagation** : `set` (si `!=`) → `mark_dirty` → `mark_dependencies_dirty` parcourt récursivement (DFS, **récursion native**) les dépendants non déjà sales et appelle `vtable.mark_dirty` (c'est ce qui déclenche `request_redraw`) [LU `core/properties.rs:807-818,851-870`, `core/window.rs:502-507`]. Coût d'un changement ≈ O(taille du sous-graphe sale) ; une propriété déjà sale arrête la propagation.
- **Propriétés constantes** : le compilateur émet `set_constant()` pour les propriétés prouvées constantes ; leur liste de dépendants devient le sentinelle et `register_as_dependency` ne fait rien (pas d'allocation) [LU `comp/generator/rust.rs:1709-1712,2149-2152`, `core/properties.rs:788-806,820-835`]. Intérêt : géométrie absolue littérale = quasi gratuite à suivre ; géométrie issue d'un layout ou d'un modèle = suivie (4 nœuds/item/frame, §1.4).
- **Coût de N liaisons** [LU/HYP] : mémoire ≈ N × (`Box<BindingHolder>` ≳ 48 o + closure) + nœuds ≈ 48 o par dépendance (malloc glibc) ; évaluation ≈ un appel indirect + 1 malloc/free par dépendance. Aucun arena/pool : **le coût dominant d'un binding réévalué est l'allocateur** (`__libc_malloc`/`_int_free` visibles dans un profil).
- `PropertyTracker` (rendu, répéteurs, textes) réutilise le même mécanisme ; `evaluate_as_dependency_root` vide/recrée les nœuds à chaque évaluation [LU `core/properties.rs:1273-1385`].
- `ChangeTracker` (callbacks `changed`) : exécutés dans `update_timers_and_animations` et en boucle (≤10 tours) dans `ensure_tree_instantiated` [LU `core/context.rs:221`, `core/window.rs:794-815`].
- **Animations** : `AnimationDriver.global_instant` est une `Property<Instant>` unique ; chaque propriété animée lit `animation_tick()` (donc dépend de `global_instant`) ; à chaque tick `update_animations` fait `set` ⇒ **marque sales les N propriétés animées** (liste intrusive de N nœuds), qui marquent à leur tour leurs items/trackers, puis chacune est réévaluée au dessin [LU `core/animations.rs:240-304`, `core/properties/properties_animations.rs:377,424,532,690`]. Flick/molette : animation physique à décélération constante (2000 px/s², molette = 180 ms) [LU `core/items/flickable.rs:44-55,536-567`].

## 4. Mise en page

- Les layouts sont **compilés en liaisons** : le compilateur produit, par layout, des propriétés `layout_cache` (`SharedVector<Coord>`) et `layoutinfo_h/v` ; la géométrie de chaque enfant est une liaison qui lit `layout_cache[i]` [LU `comp/passes/lower_layout.rs`, `comp/layout.rs`, `core/layout.rs:1229-1340`].
- **Boîte (H/V)** : `solve_box_layout` alloue `SharedVector` résultat + `Vec<LayoutData>` par résolution ; `layout_items` boucle `adjust_items` (grow/shrink) tant que des items saturent min/max : **O(n) par passe, O(n²) pire cas** (chaque passe fige ≥ 1 item) [LU `core/layout.rs:208-270,1229-1340`]. Grille : `solve_grid_layout` (organisation + deux axes) [`:1035-1096`] ; flexbox : `solve_flexbox_layout_with_measure` [`:1998`].
- **Invalidation** : une modification de `width/height` du conteneur ou d'une `layoutinfo` d'enfant marque sale le `layout_cache` ⇒ **toutes** les liaisons x/y/width/height des enfants (lecture du cache). La résolution est paresseuse (au premier `get` pendant `compute_dirty_regions`). Un redimensionnement de fenêtre ⇒ réévaluation de **chaque layout et de la géométrie de chaque item laid-out** puis `geometry_changed` pour chacun (marquage ancien+nouveau rectangle, réécriture du cache) [LU `core/partial_renderer.rs:542-590`] ⇒ O(N_items) avec de gros facteurs (allocs `Vec`/`SharedVector` par layout, liaisons par enfant).
- `layout_info` d'un `Text` appelle `renderer.text_size` (mise en forme parley) à chaque changement de texte/police/largeur : un Text *dans un layout* paie une mise en forme pour la mesure même hors écran, alors qu'un Text positionné en absolu hors écran est élagué avant toute mise en forme [LU `core/items/text.rs` (layout_info), `core/partial_renderer.rs:774-805` (« this skips e.g. shaping off-screen text »)].
- `ListView` : voir §6. Un `for` hors `ListView` instancie **toutes** les lignes (`update_all_instances`) et **refuse > 1 048 576 lignes** (`MAX_EAGER_INSTANCE_COUNT = 1<<20`, `debug_log!` puis 0 instance) [LU `core/model/repeater.rs:171-190`].
- Coordonnées : `Coord = f32` sauf `--cfg slint_int_coord` (i32) [LU `core/lib.rs:104-107`] ; non documenté publiquement (aucune occurrence dans `docs/`). Précision entière f32 jusqu'à 2²⁴ ≈ 16,7 M px (voir prédiction L1).

## 5. Texte

- **Pile** : `parley 0.11.1` (mise en forme, bidi, segmentation ICU) + `harfrust 0.12.0` (portage Rust de HarfBuzz) + `fontique 0.11.1` (fontes système) ; **`rustybuzz` n'est plus que dépendance de test** pour le chemin de production ; l'ancien chemin `core/textlayout/{shaping,linebreaker}.rs` ne sert qu'aux polices bitmap (MCU) [LU `core/Cargo.toml:175-190`, `core/textlayout/sharedparley.rs`, `sw/lib.rs:1278-1296`, `Cargo.lock`]. `SLINT_SOFTWARE_RENDERER_PARLEY_DISABLED` désactive parley pour les polices vectorielles (lu une fois) [LU `sw/lib.rs:1278-1285`].
- **Cache de mise en forme** : `TextLayoutCache` = `ItemCache` clé `ItemRc` ; chaque entrée contient les **paragraphes mis en forme (avant coupure de lignes)** ; invalidée par les dépendances de propriétés lues pendant la mise en forme ; limite douce `ENTRY_LIMIT = 1024` entrées (~4,7 Ko/entrée), balayage (`sweep`) des entrées non servies durant les 2 dernières frames ; la coupure de lignes est réutilisée si largeur/alignement inchangés (`RetainedLineBreaking`) ; une entrée ne sert qu'**un seul mode de wrap** à la fois [LU `core/textlayout/sharedparley/cache.rs:17-135,218-262`, `layout.rs:59-110,120-150`]. `text_content_widths` (mesure du min-content) est mis en forme **séparément** (`OverflowWrap` différent) ⇒ un `Text` mesuré + dessiné peut payer **2 mises en forme** par changement de texte [LU `core/textlayout/sharedparley.rs:441-552`].
- **Pas de mise en forme paresseuse** : `create_text_paragraphs` forme **tous** les paragraphes du texte d'un item d'un coup (`paragraph_ranges(text)`), `layout` fait `break_all_lines` sur **tous** [LU `core/textlayout/sharedparley/shaping.rs:273-324`, `layout.rs:170-176`]. Seul le **dessin** est borné à la bande visible (balayage linéaire des paragraphes, `visible_band`) [LU `draw.rs:78-95,673-700`].
- **Édition** (`TextInput`) : chaque `insert` fait `String = self.text().into()` (copie O(taille)), `insert_str` (memmove O(taille)), `set_text_internal(text.into())` (nouvelle copie) puis la dépendance `text` invalide **toute** l'entrée de cache ⇒ reformage complet du document [LU `core/items/text.rs:1943-1983`].
- **Glyphes (renderer logiciel)** : rastérisés par `swash` (`Render::new(&[Source::Outline]).format(Alpha).offset(subpixel)`) ; cache `clru::CLruCache` **plafonné à 1 MiB de poids** (`1024*1024`), clé (blob, indice, taille px, glyphe, hash des coordonnées variables, bin sous-pixel ×4) ; thread-local [LU `sw/fonts/vectorfont.rs:29-70,175-230`]. Beaucoup de glyphes distincts (CJK, emoji) saturent 1 MiB ⇒ **rastérisation swash répétée par frame** (cache thrash) [HYP sur la saturation].
- **Rich text** : `StyledText` (Markdown) n'offre que Emphasis/Strong/Strikethrough/Code/Link/Underline/Color(ARGB) : **pas de famille ni de taille par span** [LU `internal/common/styled_text.rs:7-16`]. T4 « polices/tailles alternées » n'est réalisable qu'avec plusieurs `Text` ⇒ à consigner `unsupported` pour la partie « polices/tailles par span ».
- bidi/CJK/emoji : délégués à parley/ICU (`features = ["complex-scripts"]`) et à la chaîne de repli `FALLBACK_FAMILIES` (emoji couleur : dépend du rendu `swash` en `Alpha` seulement ⇒ **les glyphes couleur ne sont probablement pas rendus en couleur dans le chemin logiciel**, car le rendu demandé est `Format::Alpha` [LU `sw/fonts/vectorfont.rs:207-210`] — [HYP] à vérifier visuellement).
- Variables : `SLINT_DEFAULT_FONT`, `SLINT_FONT_PATH` [LU `internal/common/sharedfontique.rs:82,95`].

## 6. Listes / virtualisation

- **Composant officiel** : `ListView` (hérite de `ScrollView` ⇒ `Flickable`) ; seules les lignes visibles sont instanciées ; `StandardListView` pour le cas simple [LU `comp/widgets/common/listview.slint:1-14`, `docs/.../std-widgets/views/listview.mdx:12`, `scrollview.mdx:40-41` (« ScrollView instancie toujours tous ses enfants »)].
- **Algorithme** (`update_visible_instances`, appelé à chaque `ensure_updated_listview`) [LU `core/model/repeater.rs:268-440`] :
  - hauteur d'élément **estimée par la moyenne des lignes instanciées** (`cached_item_height`) ; `content_height = cached_item_height × row_count` ; `anchor_y = cached_item_height × offset` ⇒ **hauteurs variables = barre de défilement et positions absolues approximatives** [`:299-312,424-433`].
  - défilement < 1,5 écran : marche incrémentale sur les instances existantes ; **saut > 1,5 écran (`first_item_y > -content_y + 1.5·h`) ⇒ « random seek » : `splice(0, len, 0)` détruit TOUTES les instances et en recrée ~une page**, offset = `floor(-content_y / hauteur_moyenne)` (approximatif) [`:325-335`].
  - recyclage : **aucun pool de composants** ; une ligne sortie est détruite, une entrante est créée (`init()` + `update(row,data)`) [`:449-487`].
- **`row_changed`** : mise à jour directe de l'instance si la ligne est dans la fenêtre instanciée [LU `core/model/repeater.rs:533-547`]. **`row_added/removed`** : splice du `Vec` d'instances + **marque Dirty toutes les instances après l'index** (re-`update` de la page visible) ; si l'index précède l'offset visible : décale l'offset et marque toutes sales [`:549-610`]. **`reset`** : `instances.clear()` ; le nombre de lignes n'a aucun effet sur le coût (seule la page est recréée) [`:612-615`].
- `VecModel` : `insert/remove` = `Vec::insert/remove` **O(N) memmove** + notification ; `set_vec`/`clear` = `reset` [LU `core/model.rs:517-584`]. `ModelNotify::row_changed` ne marque la propriété « données » sale que si la ligne est suivie (`tracked_rows` : `Vec<usize>` trié, `binary_search`, insertions O(n) lors du suivi) [LU `core/model/model_peer.rs:75-95,132-150`]. Adaptateurs `Filter/Sort/Map/Reverse` : `FilterModel` et `SortModel` maintiennent des tables de correspondance O(N) (reconstruction sur `reset`, `binary_search` sur modifications) [LU `core/model/adapters.rs:290-400,610-790`].
- **Hauteurs variables** (`h(i)=48+16·(fnv%6)`) : supportées (chaque instance fixe sa hauteur) mais la position de défilement exacte d'une ligne arbitraire n'est pas disponible sans la parcourir ; `ops.sum_heights` doit être calculé côté application (le modèle), pas lu depuis `content-height` [LU `:424-433`, HYP].
- **Précision** : `content_y`, `content_height`, `anchor_y` sont des `Coord = f32` ; au-delà de ≈ 16,7 M px (≈ 200 k lignes de ≈ 80 px) les positions absolues perdent la précision entière (pas de 2, 4… 64 px) [LU `core/lib.rs:104-107`, calcul f32 HYP].

## 7. Images

- `Image` = enum `ImageInner` (None, EmbeddedImage (SharedPixelBuffer RGBA8/RGB8/prémult.), Svg, StaticTextures, NineSlice, BackendStorage…) ; `Image::load_from_path` **décode de façon synchrone sur le thread appelant** (crate `image 0.25`) ; `Image` n'est pas `Send` : décoder dans un thread en `SharedPixelBuffer` (qui est `Send`) puis `Image::from_rgba8[_premultiplied]` sur le thread UI [LU `core/graphics/image.rs:574-646,791-824`].
- **Cache de décodage** par chemin (`ImageCache`) : `CLruCache` **plafonné à 5 MiB** (poids en octets décodés) ; une image ≥ 5 MiB (≥ 1 448² RGBA) est donc rechargée/redécodée à chaque nouvelle demande par chemin, et 600 images 256² (≈ 157 MiB) ne tiennent pas ; l'application doit **garder ses `Image`** (le tampon est partagé par refcount) [LU `core/graphics/image/cache.rs:15-60`].
- **Rendu logiciel** : échantillonnage plus-proche-voisin, mise à l'échelle par pas fixe 8 bits, pas de mipmap ⇒ réduire une 8192² en 1280×720 lit le tampon avec grand pas (défauts de cache) ; **pas de rotation** ; `colorize` supporté ; `ImageInner::EmbeddedImage` RGBA prémultiplié évite la prémultiplication par pixel [LU `sw/draw_functions.rs:20-183,208-221`, `sw/lib.rs:2239-2437`]. Mémoire : 4096² RGBA = 64 Mio, 8192² = 256 Mio par exemplaire décodé (+ PNG compressé transitoire pendant le décodage) [calcul].
- Skia/FemtoVG : upload en texture/`skia_safe::Image` mis en cache par item (`image_cache`) [LU `skia/lib.rs:343-352`].

## 8. Mémoire et modèle d'exécution

- Rust natif, **allocateur système glibc** (aucun `#[global_allocator]` dans le crate de l'app ; `printerdemo_mcu/bench.rs` utilise `divan::AllocProfiler` seulement pour ses mesures) [LU]. Pas de GC, pas d'arène ; durée de vie par `Rc/VRc` (non atomique) pour les arbres d'items et `Arc`-like atomique pour `SharedString/SharedVector` (`SharedVector` : en-tête avec `AtomicIsize`) [LU `core/sharedvector.rs`, `core/string.rs`].
- **Allocations par frame** (renderer logiciel) : (i) `free`+`malloc` d'un `DependencyNode` (≈ 48 o) par dépendance relue de `redraw_tracker` et par tracker d'item réévalué ; (ii) `vec![0; w*h]` par `Path` ; (iii) `Vec<Command>` zeno par `Path` ; (iv) `Vec` d'instances cloné par `ensure_children_instantiated` ; (v) mise en forme de texte sur invalidation (parley alloue des `Layout`). Pas de pools. Une frame sans changement (hors §1.4) n'alloue rien d'autre.
- **Mémoire par item** [HYP d'après les structs] : `Rectangle` = `Property<Brush>` + `CachedRenderingData` (16 o) ≈ 50-60 o + 4 `Property<LogicalLength>` de géométrie dans le composant (≈ 64 o) ; `ComplexText` ≈ 18 `Property` ≈ 400-500 o [LU `core/items/text.rs:46-66`, `core/items.rs:336-339`] ; + entrée slab du rendu partiel (≈ 64 o) + tracker boxé (≈ 32 o + nœuds 48 o/dépendance) + entrée de cache de texte (~4,7 Ko, bornée à ≈ 1024 entrées vivantes). Ordre de grandeur U1 500 k feuilles (rect + texte) : **0,3-0,6 Go** [HYP].
- Fuites typiques : (a) file `invoke_from_event_loop` non bornée (mpsc std) si le producteur dépasse la consommation ⇒ croissance mémoire ; (b) `Image` conservées par un modèle ; (c) nœuds de dépendance accumulés ? non : vidés à chaque évaluation [LU].
- Tampon de fenêtre : un segment SHM (1280×720×4 = 3,7 Mio) réalloué à chaque changement de taille [LU `[softbuffer-0.4.8] x11.rs:313-338`].

## 9. FFI et fils

- **Appel C depuis Rust** : `extern "C"` direct ⇒ coût d'appel ≈ appel de fonction (pas de marshalling) ; aucun surcoût spécifique à Slint. Le noyau commun étant une bibliothèque Rust à interface C, l'appel inter-crates peut être non inliné (LTO possible) [HYP].
- **Natif → UI** : `slint::invoke_from_event_loop(FnOnce + Send)` → `Box<dyn FnOnce>` → `winit::EventLoopProxy::send_event(SlintEvent(CustomEvent::UserEvent(box)))` → X11 : `WakeSender::send` = `mpsc::Sender::send` **+ `calloop::ping::Ping::ping()` = un `write(eventfd)` (appel système) par événement, sans dédoublonnage** ; côté UI, `user_event` exécute la closure [LU `core/api.rs:1286-1292`, `winit/lib.rs:971-1010`, `winit/event_loop.rs:159-162`, `[winit-0.30.13] x11/mod.rs:70-90,727-730`, `[calloop-0.13.0] src/sources/ping/eventfd.rs:176-180`]. Coût producteur ≈ 1-3 µs/événement [HYP] ; consommateur ≈ ≥ 1 µs + `set_row_data` (§6).
- Idiome documenté : `Weak<Component>` + `upgrade_in_event_loop` / `invoke_from_event_loop`, un modèle (`VecModel`) modifié sur le thread UI [LU `core/api.rs:1270-1285`]. **Pas de modèle thread-safe** : tout `Model` est `Rc`.
- **Coalescence idiomatique** (à utiliser pour F2, à documenter) : accumuler les événements dans une structure partagée (`Arc<Mutex<…>>`/atomiques/anneau) et ne poster **qu'un** `invoke_from_event_loop` tant qu'un drapeau atomique n'est pas consommé, ou animer via `Timer` Slint qui lit la structure à chaque frame [HYP, conforme au code §2].
- **Gel** : un travail long sur le thread UI (variantes `ui` de F3) bloque tout (aucune préemption) ; un travail sur un fil de fond n'affecte l'UI que par concurrence CPU [LU : modèle mono-thread].
- `Timer` Slint : multi-coup/mono-coup, résolution **1 ms**, déclenché dans `new_events` ⇒ pour `ops.ui_stall_ms_max` (minuteur 4 ms) l'intervalle mesuré est quantifié à 1 ms [LU `core/timers.rs`, `core/animations.rs:176-216`].

## 11. Points de rupture prédits (rédigé le 2026-10-26 ; 4 vCPU, Xvfb 1280×720, renderer logiciel, thread UI unique)

Hypothèses de calibrage : budget 16 ms/frame sur **un seul cœur** (aucune parallélisation du rendu) ; coût fixe par item suivi 0,2-0,6 µs ; écriture de pixels ≈ 0,3-1 ns/px (aplat opaque), 3-6 ns/px (blend/texture/dégradé). Toutes les valeurs sont des **ordres de grandeur [HYP]** ; l'intervalle est l'IC « 80 % » que je défendrais.

| Famille | Mécanisme probable de rupture | N_max attendu (60 Hz) | Ce que le profil devrait montrer |
|---|---|---|---|
| **L1** list-scale | Virtualisation `ListView` : coût indépendant de N. Fling 150 000 px/s = 2 500 px/frame > 1,5 écran ⇒ « random seek » : toute la page détruite/recréée à chaque frame (≈ 15 lignes). Rupture par **mémoire** (VecModel 10 M × T) et **précision f32** (>16,7 M px ⇒ défilement par pas ≥ 2 px, lignes qui « sautent ») plus que par CPU. | **≥ 10 M non atteint** (tient en CPU) ; dérive visuelle dès ≈ 200 k lignes ; setup ≈ 0,05-0,5 s | `update_visible_instances`, création/destruction de composants (`malloc/free`), parley si texte, blit ; **pas** de fonction O(N) sauf `Vec::from` au setup |
| **L2** list-rich | Création de ~7 lignes/frame à 20 000 px/s ; chaque ligne de K items : liaisons (malloc) + **mise en forme de ~K/2 textes neufs** ; repeinture plein cadre (le viewport Flickable bouge : tous les items marqués `moved`) ; pas de blit de défilement. | **K_max ≈ 48 (24-96)** ; K=96 marginal/échec | `shape_paragraphs`/`harfrust`/`parley` (≈ 40 %), `draw_rounded_rectangle_line`, `draw_glyph_run`/`draw_texture_line`, `compute_dirty_regions`, malloc/free |

## 12. Pièges d'implémentation (revue d'équité)

1. **Renderer par défaut ≠ logiciel** : sans `SLINT_BACKEND=winit-software` (ou `BackendSelector::renderer_name("software")`), `default_renderer_factory` prend FemtoVG/OpenGL (llvmpipe) [`winit/lib.rs:139-157`]. Consigner le renderer effectif dans `NOTES` (`SLINT_DEBUG_PERFORMANCE=…,console` l'imprime via `winsys_info` mais **ne pas l'activer pendant les mesures**).
2. **`SLINT_DEBUG_PERFORMANCE=refresh_full_speed`/`overlay`** modifie le comportement (repaint complet forcé, texte dessiné) : proscrit en mesure [`sw/lib.rs:712-725`].
3. **`ScrollView + for`** au lieu de `ListView` : instancie tout (≥ 1 048 576 refusé) [`core/model/repeater.rs:171-190`, `scrollview.mdx:40-41`].
4. **Un `invoke_from_event_loop` par événement à haut débit** : appel système + allocation chacun, file non bornée, boucle qui ne rend plus la main [`[winit] x11/mod.rs:70-90,549-552`] ; privilégier lot/coalescence, et documenter la coalescence si elle « perd » des événements (règle F2).
5. **Remplacer le modèle à chaque frame** (`set_vec`/nouveau `ModelRc`) : détruit les instances ; utiliser `set_row_data` / `insert` / `remove` [`core/model/repeater.rs:549-615`].
6. **Layouts partout** : toute la géométrie devient des liaisons suivies et recalculées au redimensionnement ; pour des grilles de formes/étiquettes, le positionnement absolu (constant ou lié à des modèles) évite mesure de texte et `layout_cache` ; l'inverse est un anti-pattern **sauf si l'on teste explicitement le layout (U1)** — le dire.
7. **Texte à mise à jour fréquente** : chaque changement de `text` reforme tout l'item ; éviter de multiplier les `Text` quand un seul suffit, **mais ne pas tricher** en pré-rendant du texte en image (T2/U2) ; pour T3 utiliser `TextInput` natif (pas un `Text` + gestion manuelle).
8. **Ne pas émuler les non-supportés** (ombre, rayon de clip, rotation, flou, pointillés, `Layer`) par des images pré-rendues ou des astuces : produire `unsupported`/`not_rendered` [`sw/lib.rs:3059-3102`].
9. **Images** : décoder **hors thread UI** (`image` crate → `SharedPixelBuffer` → `Image::from_rgba8_premultiplied` sur le thread UI) ; **garder** les `Image` (le cache par chemin plafonne à 5 MiB) ; préférer le format **prémultiplié** (évite `premultiply` par pixel) [`core/graphics/image.rs:791-806`, `image/cache.rs:53`, `sw/draw_functions.rs:208-221`].
10. **Chemins** : N `Path` = N masques de la taille de la boîte par frame ; un seul `Path` géant dont la chaîne de commandes est reconstruite à chaque frame est O(N) en parsing — alternative équitable : `PathLineTo` éléments (items) = O(N) items ; comparer et journaliser [`sw/path.rs:61-124`, `core/graphics/path.rs:360-395`].
11. **Mesure de gel UI** : un `Timer` 4 ms est quantifié à 1 ms et ne s'exécute que dans `new_events` ; la valeur mesurée inclut une frame complète ; ne pas utiliser `std::thread::sleep` sur le thread UI [`core/timers.rs`, `core/animations.rs:213-216`].
12. **Latence** : un carré qui change « après application » doit passer par le chemin d'événements normal (`key-pressed`) ; ne pas forcer `window.request_redraw()` ni déclencher un rendu manuel (`take_snapshot`) — l'attente du timer de 16 ms fait partie du comportement de la stack, la reproduire telle quelle [`winit/frame_throttle.rs:46-71`].
13. **Redimensionnement (U1)** : utiliser `Window::set_size` ou les événements X réels ; chaque redimensionnement force deux frames pleines (NewBuffer puis cache reconstruit) [`sw/lib.rs:628-631`, `[softbuffer] x11.rs:313-338`].
14. **Équité inter-stacks** : le renderer Slint logiciel est **mono-thread** et rasterise **sans occlusion** ; ne pas comparer à un moteur multi-thread/GPU sans le dire ; les mêmes N visuels ne sont pas atteignables avec des primitives non rendues.
15. `SLINT_SCALE_FACTOR`/DPI : Xvfb à échelle 1 ; ne pas changer entre piles (le cache de texte est vidé au changement d'échelle) [`core/textlayout/sharedparley/cache.rs:80-90`].
16. **`slint_int_coord`** (`RUSTFLAGS=--cfg slint_int_coord`) supprime la limite f32 de L1 mais est **non documenté/interne** : ne l'utiliser que si noté explicitement (règle 1.3 de la spec).
